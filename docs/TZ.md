# Техническое задание: Калькулятор стоимости TopPost.de

**Версия:** 1.0
**Дата:** 12 марта 2026
**Дедлайн:** 30 апреля 2026
**Приоритет:** P0 (критический)

---

## 1. Цель и бизнес-контекст

### Проблема

Текущий сайт TopPost.de не отображает стоимость услуг. Для расчёта клиент вынужден обращаться к менеджеру в Telegram/WhatsApp. Это создаёт критический барьер конверсии:

- 70-80% потенциальных клиентов уходят, не узнав цену
- Конкуренты (PMPaket, Qwintry) показывают цену мгновенно
- Невозможно масштабировать продажи без self-service инструмента
- Ночные/выходные посетители полностью теряются

### Цель

Публичный калькулятор стоимости «под ключ» на главной странице toppost.de, который за < 5 секунд показывает клиенту итоговую стоимость заказа с разбивкой по компонентам.

### Ожидаемый эффект

| Метрика | До | После (через 3 мес.) |
|---|---|---|
| Конверсия посетитель → заявка | ~2% | 4-5% |
| Заявок/день с сайта | ~50 | 100-150 |
| Обращений к менеджеру «сколько стоит» | ~200/день | ~50/день |
| Среднее время до заказа | 24-48ч | 5-15 мин |

## 2. Пользовательские сценарии

### Сценарий A: «Знаю что хочу» (основной, 60% аудитории)

Мария из Москвы нашла куртку Moncler на Mytheresa за 1,200€. Заходит на toppost.de, вставляет ссылку в калькулятор. За 3 секунды видит: «Итого до двери: 1,478€ (куртка 1,200€ + комиссия 89€ + доставка 0€ + пошлина 189€). Срок: 10-14 дней.» Нажимает «Заказать» и переходит к оплате.

### Сценарий B: «Прицениваюсь» (30% аудитории)

Алексей из Казани хочет понять, выгодно ли заказывать кроссовки из Германии. Вводит вручную: категория «обувь», стоимость 120€, вес 1.5 кг. Видит итоговую стоимость. Сравнивает с ценой в России. Убеждается в выгоде. Сохраняет расчёт или делится в Telegram.

### Сценарий C: «Пришёл по рекомендации» (10% аудитории)

Дмитрий получил от друга ссылку на конкретный расчёт TopPost (например, toppost.de/calc?url=...). Калькулятор автоматически заполнен — Дмитрий сразу видит итог и может заказать.

## 3. Функциональные требования

### 3.1. Режимы ввода

Калькулятор поддерживает два режима, переключаемых табами:

**Режим 1: «По ссылке» (основной, по умолчанию)**

| Поле | Тип | Обязательное | Описание |
|---|---|---|---|
| URL товара | text input | Да | Ссылка на товар в европейском магазине |
| Страна доставки | select | Да (предзаполнено «Россия») | Россия, Казахстан, Киргизия |
| Город доставки | autocomplete | Нет | Для расчёта последней мили |

При вставке ссылки — автопарсинг:
- Название товара
- Цена в валюте магазина (EUR, GBP, USD)
- Изображение (если доступно)
- Категория товара (для расчёта пошлины)
- Оценочный вес (по категории)

Если парсинг не удался — fallback на ручной ввод (Режим 2) с уведомлением: «Не удалось определить параметры автоматически. Укажите вручную.»

**Режим 2: «Вручную»**

| Поле | Тип | Обязательное | Описание |
|---|---|---|---|
| Стоимость товара | number + currency select | Да | EUR/GBP/USD с конвертацией |
| Категория товара | select | Да | Для расчёта пошлины (список ниже) |
| Вес | number + slider | Да (предзаполнено по категории) | 0.1 - 31 кг, шаг 0.1 |
| Страна доставки | select | Да (предзаполнено «Россия») | Россия, Казахстан, Киргизия |

### 3.3. Логика расчёта

#### Комиссия TopPost

```
комиссия = MAX(стоимость_товара × 0.07, 5€)  // минимум 5€
обработка = 5€  // фиксированная
```

**Примечание:** Ценовая модель утверждается отдельно (A/B тест с «всё включено»). Калькулятор должен поддерживать переключение между моделями через конфигурационный файл / админ-панель.

#### Доставка

```
если стоимость_товара >= 100€:
    стандарт = бесплатно
    экспресс = тариф_экспресс[вес][страна]
    эконом = бесплатно
иначе:
    стандарт = 15€
    экспресс = 15€ + тариф_экспресс[вес][страна]
    эконом = 10€
```

**Тарифная сетка экспресс (€, за посылку):**

| Вес | Россия | Казахстан | Киргизия |
|---|---|---|---|
| до 1 кг | 15€ | 18€ | 22€ |
| 1-3 кг | 20€ | 24€ | 28€ |
| 3-5 кг | 25€ | 30€ | 35€ |
| 5-10 кг | 35€ | 42€ | 48€ |
| 10-20 кг | 50€ | 60€ | 70€ |
| 20-31 кг | 70€ | 85€ | 95€ |

**Примечание:** Тарифы вынесены в конфигурационный JSON — изменяемы без деплоя.

#### Таможенная пошлина

Расчёт по правилам ЕАЭС (для физических лиц):

```
если стоимость_товара <= 200€ И вес <= 31 кг:
    пошлина = 0€  // беспошлинный лимит
иначе:
    превышение_стоимости = MAX(0, стоимость_товара - 200€)
    пошлина_стоимость = превышение_стоимости × 0.15
    превышение_веса = MAX(0, вес - 31) × 2€/кг
    пошлина = MAX(пошлина_стоимость, превышение_веса)
```

**Примечание:** Лимит 200€ действует на одного получателя в месяц. Калькулятор показывает tooltip: «Беспошлинный лимит — 200€ на получателя в календарный месяц. Если вы уже получали посылки в этом месяце, пошлина может быть выше.»

Таможенные правила вынесены в конфигурацию для быстрого обновления при изменении законодательства.

#### Конвертация валют

```
итого_рубли = итого_евро × курс_ЦБ_РФ × 1.02  // +2% буфер на колебания
курс обновляется раз в час через API ЦБ РФ
```

Отображение: «≈ X ₽ (курс ЦБ + 2%)»

### 3.4. Автопарсинг ссылок

#### Архитектура

```
[Клиент: вставка URL]
    → [Backend API: POST /api/v1/parse]
        → [Router: определение магазина по домену]
            → [Парсер магазина: Playwright/Puppeteer]
                → { name, price, currency, image_url, category, estimated_weight }
            → [Fallback: Open Graph / meta tags]
                → { name, price, image_url }
            → [Fallback: 404 / ошибка]
                → { error: "unsupported_store" }
    → [Клиент: заполнение формы результатами]
```

#### Fallback-стратегия

1. **Парсер магазина** (Playwright) — точные данные, обновляемые скрипты
2. **Open Graph / JSON-LD** — название, цена, изображение из meta-тегов
3. **Ручной ввод** — форма заполняется пользователем

При неуспешном парсинге:
- Показать: «Магазин [домен] пока не поддерживается для автоматического расчёта. Укажите данные вручную.»
- Автоматически переключить на Режим 2 (вручную)
- Логировать URL для приоритизации разработки новых парсеров

#### Кэширование

- Результат парсинга кэшируется на 1 час (цены могут меняться)
- Ключ кэша: SHA256(URL)
- Хранилище: Redis
- При повторном запросе того же URL — мгновенный ответ

### 3.5. Функция «Поделиться расчётом»

При нажатии «Поделиться»:
- Генерируется короткая ссылка: `toppost.de/c/abc123`
- Ссылка содержит все параметры расчёта
- При переходе — калькулятор автоматически заполнен
- Кнопки шеринга: Telegram, WhatsApp, копировать ссылку
- OG-превью при шеринге: «Nike Air Max 90 из Германии — 133€ с доставкой | TopPost.de»

Хранение: Redis с TTL 30 дней.

### 3.6. Функция «Сравнение с ценой в России»

Для популярных товаров/категорий — автоматическое сравнение:

```
Средняя цена в России: ~17 000 ₽
Через TopPost: ~13 340 ₽
Экономия: ~3 660 ₽ (22%)
```

Источник данных:
- Фаза 1: ручная таблица средних цен по категориям (заполняется контент-менеджером)
- Фаза 2: парсинг Яндекс.Маркет / Wildberries / Ozon (backlog)

Если данных для сравнения нет — блок не показывается.

### 3.7. Кнопка «Заказать»

При нажатии — переход к оформлению заказа:

**Для незарегистрированных:**
- Модальное окно быстрой регистрации: имя, телефон, email (или Telegram)
- Данные калькулятора автоматически переносятся в заказ

**Для зарегистрированных:**
- Прямой переход в оформление заказа с предзаполненными данными

**Альтернативный CTA (если self-service оформление ещё не готово к 30 апреля):**
- «Заказать через Telegram» — открывает Telegram-бот с предзаполненным сообщением:
  `Хочу заказать: [название товара], [URL], итого [сумма]€`
- «Заказать через WhatsApp» — аналогично

## 4. Нефункциональные требования

### 4.1. Производительность

| Метрика | Требование |
|---|---|
| Время расчёта (client-side, ручной ввод) | < 50 мс |
| Время парсинга ссылки (server-side) | < 5 сек (95-й перцентиль) |
| Время загрузки страницы с калькулятором | LCP < 2.5 сек |
| Cumulative Layout Shift | < 0.1 |

Расчёт по формулам — полностью на клиенте (JavaScript). Тарифные таблицы загружаются при инициализации страницы (< 10 KB JSON).

Парсинг ссылок — серверный, с индикатором загрузки (spinner + текст «Получаем данные из магазина...»).

### 4.2. Адаптивность

- Mobile-first дизайн (70%+ трафика — мобильные)
- Breakpoints: 320px, 768px, 1024px, 1440px
- Touch-friendly: кнопки ≥ 44px, поля ≥ 48px высоты
- Слайдер веса — touch-оптимизированный

### 4.3. SEO

- Калькулятор должен быть на странице `/calculator` (отдельная посадочная)
- Также встроен виджетом на главной странице (sticky/inline)
- Structured Data: `FAQPage` schema для блока FAQ под калькулятором
- Title: `Калькулятор стоимости доставки из Германии в Россию | TopPost.de`
- H1: `Рассчитайте стоимость доставки из Европы`
- Контентный блок под калькулятором (500-1000 слов) для SEO

### 4.4. Аналитика

Каждое действие в калькуляторе отправляется в Яндекс.Метрику и Google Analytics 4:

| Событие | Параметры |
|---|---|
| `calc_view` | source (main/page/widget) |
| `calc_url_paste` | domain магазина |
| `calc_url_parse_success` | domain, время парсинга |
| `calc_url_parse_fail` | domain, причина ошибки |
| `calc_manual_input` | категория, стоимость (диапазон), страна |
| `calc_result_view` | итого (диапазон), тариф, страна |
| `calc_tariff_select` | экспресс/стандарт/эконом |
| `calc_option_toggle` | страховка/фото/упаковка |
| `calc_order_click` | итого, тариф, канал (web/telegram/whatsapp) |
| `calc_share_click` | канал (telegram/whatsapp/copy) |

**Воронка калькулятора (настроить как цель):**
`calc_view → calc_result_view → calc_order_click`

### 4.5. A/B тестирование

Калькулятор должен поддерживать A/B тесты через feature flags:

- **Ценовая модель A:** 7% комиссия + 5€ фикс (гибридная)
- **Ценовая модель B:** фиксированная цена за кг «всё включено»
- **CTA вариант A:** «Заказать» (прямой)
- **CTA вариант B:** «Рассчитать точную стоимость» (мягкий)

Распределение трафика: 50/50, управление через конфиг / admin panel.

### 4.6. Безопасность

- Rate limiting на endpoint парсинга: 10 req/min на IP, 100 req/min глобально
- Валидация URL: только HTTP/HTTPS, whitelist доменов разрешённых магазинов
- Sanitization всех пользовательских вводов (XSS prevention)
- CORS: только toppost.de и express.toppost.de
- Парсеры работают в изолированном окружении (sandbox)

### 4.7. Локализация

- Основной язык: русский
- Валюты: EUR (основная), с отображением эквивалента в ₽, ₸ (Казахстан), сом (Киргизия)
- Формат чисел: 1 234.56€ (русский формат с пробелом)
- Даты сроков: «10-14 рабочих дней»

| Аналитика | GTM + dataLayer | Гибкая настройка событий |

Если текущий сайт TopPost на другом стеке — калькулятор может быть реализован как **embed-виджет** (iframe или Web Component), который встраивается в существующий сайт.

### Backend (парсинг)

| Компонент | Технология | Обоснование |
|---|---|---|
| Runtime | Node.js или Python | Экосистема для скрапинга |
| Парсинг | Playwright | Headless browser, обход JS-рендеринга |
| API | FastAPI (Python) или Express (Node.js) | Быстрый, типизированный |
| Кэш | Redis | Кэширование парсинга и расчётов |
| Очередь | Bull (Node.js) или Celery (Python) | Асинхронный парсинг при нагрузке |
| Мониторинг парсеров | Sentry + custom alerts | Алерт при поломке парсера |

### Инфраструктура

| Компонент | Рекомендация |
|---|---|
| Хостинг парсеров | VPS (Hetzner) или Fly.io |
| CDN | Cloudflare |
| Мониторинг | Sentry (ошибки) + Grafana (метрики) |
| CI/CD | GitHub Actions |

## 8. Поддержка парсеров

### Мониторинг

Каждый парсер проверяется автоматическим smoke-тестом раз в 6 часов:
- Тестовый URL для каждого магазина
- Проверка: цена ≠ null, название ≠ null
- При провале: алерт в Telegram-канал разработчиков
- Dashboard: % успешных парсингов по магазинам за 24ч / 7д / 30д

### Обновление парсеров

Магазины регулярно меняют вёрстку. Процесс:
1. Алерт о поломке парсера
2. Разработчик обновляет селекторы (обычно 30-60 мин)
3. Деплой hotfix
4. Smoke-тест

SLA: поломанный парсер чинится в течение 24 часов (рабочие дни).

### Логирование для приоритизации

Все запросы парсинга логируются:
```
{ timestamp, url, domain, success, fallback_used, parse_time_ms }
```

Еженедельный отчёт: топ-10 доменов с неудачным парсингом → приоритет разработки новых парсеров.

## 13. Глоссарий

|---|---|

| CTA | Call to Action — призыв к действию (кнопка) |
| LCP | Largest Contentful Paint — метрика скорости загрузки |
| PWA | Progressive Web App |

## Приложение A: Конкурентный анализ калькуляторов

### PMPaket (лучший бенчмарк)
- Минимум полей: страна, тип, вес
- Мгновенный расчёт (client-side, таблица цен в JS)
- 3 тарифа в виде карточек (Премиум / Стандарт / Документы)
- Без регистрации
- **Нет:** автопарсинга, разбивки по компонентам, сравнения цен

### Qwintry
- Поле: только вес
- Несколько методов доставки
- Отдельный калькулятор таможенных пошлин
- Sticky-блок при прокрутке
- **Нет:** автопарсинга, комиссии за выкуп (другая модель)

### CDEK Forward
- **Нет публичного калькулятора** — только после регистрации
- Это антипаттерн, который TopPost должен избежать

### SanktionGO
- **Нет калькулятора** — форма заказа по ссылке
- Есть автопарсинг (ссылка → товар)
- Цена обсуждается с менеджером
- **Минус:** непрозрачно

### Конкурентное преимущество калькулятора TopPost

Ни один конкурент не предлагает:
1. Автопарсинг ссылки + мгновенный расчёт полной стоимости «под ключ»
2. Разбивку: товар + комиссия + доставка + пошлина
3. Сравнение с ценой в России
4. Шеринг расчёта в мессенджеры

Это даёт TopPost уникальное позиционирование: **«Узнай точную стоимость за 30 секунд»**.
